How to Use this Postal PoC

This page explains the minimal workflow for using the Cloudflare-native Postal proof-of-concept. It covers onboarding, sending messages, domain setup, tracking, and monitoring.

1. Onboarding & API keys

Create an organization and generate an API key (PoC: use the demo key header x-api-key). In production, API keys are stored in a control-plane database (D1) and can be rotated or revoked.

2. Domain setup

Use the Domain setup wizard to validate SPF, DKIM, and DMARC records. Add DNS TXT records provided by the wizard to complete verification.

3. Sending messages

Send messages to the edge intake endpoint. PoC endpoints:

POST /api/send
Headers: x-api-key: <key>
Body: { "from": "me@example.com", "to": "you@example.com", "subject": "Hi", "text": "Hello" }

Example: cURL

Replace YOUR_API_KEY and https://your-pages-url with your values.

curl -X POST "https://your-pages-url/api/send" \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_API_KEY" \
  -d '{"from":"me@example.com","to":"you@example.com","subject":"Hello","text":"Hello from Postal PoC"}'

The PoC will forward to an HTTP relay if configured (environment variable RELAY_URL), otherwise it simulates acceptance.

4. Tracking & events

Track opens and clicks using the tracking endpoints:

GET /api/tracking-pixel?mid=<message_id>
GET /api/tracking-redirect?url=<encoded_url>&mid=<message_id>

Events are enqueued for ingestion and processing in the events pipeline in production.

5. Observability

Use Logs and Metrics (Logpush + external analytics) to monitor queue lag, delivery rates, and bounce spikes. For PoC review logs in the Cloudflare Workers dashboard or local wrangler dev output.

6. Next steps

  • Protect API keys with D1 and add Durable Object rate-limiters.
  • Decide on delivery strategy (SMTP API vs self-hosted MTA).
  • Set up Queues and Router for production routing and throttling.
